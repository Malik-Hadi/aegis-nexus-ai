This isn’t a problem with your project. You pasted a SQL query into the PowerShell terminal, and PowerShell doesn’t understand SQL.

PowerShell has a built-in command called Select-Object, and its short name is select. When you typed SELECT actor, ..., PowerShell tried to run that command, got confused by the word FROM, and gave the “positional parameter” error. SQL queries only work inside a database tool.

Option 1: Run it in SQLTools (easiest)
Click the database icon in the left sidebar and open your aegis connection.
Make sure it’s connected (click the plug icon if needed).
Open a new SQL file: right-click the connection and choose New SQL File, or press Ctrl+Shift+P and type SQLTools: New SQL file.
Paste this into that file, not the terminal:
SELECT actor, action, result, timestamp FROM audit_logs ORDER BY id DESC LIMIT 10;
Press Ctrl+E and then Ctrl+E again. The results appear in a new tab.
Option 2: Run it from the terminal without SQLTools
Paste this into the PowerShell terminal as one line:

docker compose -f deploy/docker-compose.yml --env-file .env exec -T db psql -U aegis -d aegis -c "SELECT actor, action, result, timestamp FROM audit_logs ORDER BY id DESC LIMIT 10;"
It prints the same table in the terminal. If you changed POSTGRES_USER or POSTGRES_DB in .env, use those values instead of aegis.

How to tell where to paste things
Commands starting with go, git, docker or $body = ...: terminal.
Anything starting with SELECT, INSERT or similar: a SQL file in SQLTools, or Option 2.

What this block adds
Enrolment: an Admin creates a one-time token (valid for 1 hour). An agent trades it for its own secret credential. Only a hash of that credential is stored.
POST /v1/events: the agent sends events with Authorization: Bearer <credential>. The tenant and agent come from the credential, never from the request body. Bad data gets a 400, duplicates are caught by the idempotency key, and a good event gets a 202.
GET /v1/events and GET /v1/agents: tenant-scoped, taking the tenant only from the login cookie.
POST /v1/agents/{id}/revoke: Admin only. A revoked agent is rejected on its next request.
Tests for AT-03 (tenant isolation) and AT-06 (revoked agent denied).
