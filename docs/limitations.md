# Known limitations
- Lab prototype, not production-ready. No independent penetration test or compliance assessment.
- Real endpoint collection is not implemented. The agent sends heartbeats and replays synthetic fixtures; the five rules detect those synthetic patterns, not proof of a real intrusion.
- Containment is simulated only. No real change is made to any machine.
- The API serves plain HTTP on loopback. TLS is available through the lab proxy (cmd/tlsproxy, self-signed) or by setting API_TLS_CERT and API_TLS_KEY. The dashboard talks to the API over HTTP.
- Logging out clears the browser cookie only. Sessions are not tracked on the server and expire after 8 hours.
- Rate limits and bans are in memory on a single API process. A reverse proxy shares one login budget across its clients.
- Inbound inspection checks the URL, query string and User-Agent for known patterns only. It does not inspect request bodies and never bans loopback peers. Blocked requests appear in audit_logs (security.inspect) but not yet in the console.
- The ZAP scan covers the public surface only (it does not sign in). Authenticated endpoints are covered by the Go tests.
- The AI analyst is optional. Without a model key it uses a deterministic template and cannot change anything.
- The Docker image copies Linux programs built by scripts/build-binaries.ps1, because the in-image compile step produced no output on the test host (cause not investigated).
- AT-11: an earlier load run reached only 58.81% because the API process was gone for part of the run; cause not proven. The repeated run passed (100%).
- tests/security is empty; the security tests (IDOR, tenancy, rate limits, injection, revocation) live in the Go test suite.
